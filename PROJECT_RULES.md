## Core Development Rules

1. **Tech Stack**: Use React + Vite.
2. **Architecture Quality**: Keep the project modular, maintainable, and production-oriented.
3. **Visual Identity**: Follow the existing ExpoVerse / AI & Robotics event visual identity.
4. **Brand Asset Reuse**: Reuse official event logos, banners, and images when provided.
5. **No AI Branding Replacements**: Do not create AI-generated replacement versions of official branding when original assets are available.
6. **Fact Verification**: Do not invent confirmed speakers, sponsors, exhibitors, partners, prices, statistics, schedules, prize amounts, or other official information.
7. **Placeholder Convention**: For information that has not been confirmed, use "Coming Soon", "To Be Announced", or an appropriate placeholder.
8. **Reference Only**: The existing website is a visual and information-architecture reference, not source code to copy.
9. **Visual Standard**: The website should have a professional international technology-conference appearance.
10. **Responsiveness**: The website must be responsive for desktop, tablet, and mobile.
11. **Accessibility**: Follow accessibility best practices (semantic HTML, proper ARIA, contrast, keyboard navigation).
12. **Performance & Restraint**: Avoid unnecessary dependencies and excessive animations.
13. **Navigation Integrity**: Keep navigation functional and avoid broken links.
14. **Data Privacy**: Do not expose private registration information publicly.
15. **Secure Persistence**: Registration data must eventually be handled through a secure backend and database, not localStorage as a production database.
16. **Moderated Participants**: Only approved organizations/participants should appear in the public participants/exhibitors section.
17. **Registration Pipeline**: The future registration workflow should support:
    `Registration → validation → backend/API → database → admin approval → public display`.
18. **Public Participant Privacy**: Public participant information should contain only approved public fields such as organization name, logo, category, and location if approved.
19. **Architectural Transparency**: Explain major architectural changes before making them.
20. **Verification**: Test the application after major changes.
21. **Asset Safety**: Do not delete existing assets or important project files without checking first.
22. **Component Modularity**: Keep the code clean and component-based.
23. **Realistic Structure**: Use realistic content structure suitable for an international AI and robotics conference.
24. **Incremental Evolution**: Do not replace the entire application architecture unnecessarily.
25. **Context First**: Before implementing a feature, inspect the existing code and work with the current structure.
